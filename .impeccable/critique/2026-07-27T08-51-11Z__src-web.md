## P1 — significant (both fixed in this round)

1. **Invisible keyboard focus on the highlight card.** `.hl { overflow: hidden }` clipped the
   `.hl-summary` focus ring, which the global rule drew at `outline-offset: 2px` *outside* a
   button sitting flush to the card's padding box. With `:focus-visible` genuinely active the
   signature component rendered no ring at all, while table rows (offset `-2px`) showed one
   clearly. Violated DESIGN.md's "visible focus on every interactive element, no exceptions".
   **Fixed:** `.hl-summary:focus-visible { outline-offset: -2px; border-radius: var(--r-lg) }`.
   Verified: ring renders in both themes; a new Playwright test walks every focusable to its
   clipping ancestor and fails if the ring escapes.
2. **Placeholder text below 4.5:1 in both themes.** Only `.search input::placeholder` was
   themed; `.control` inputs and the palette fell back to the UA default `#757575` —
   measured 4.48:1 light / 3.98:1 dark for the palette, 4.1:1 / 4.17:1 for the SMTP password
   hint, and a cold grey on a warm near-black in dark mode. **Fixed:** a base `::placeholder`
   rule at `var(--ink-subtle)` with `opacity: 1`. Verified: **5.50:1 light / 5.54:1 dark**,
   with a new test that measures every placeholder on every route in both themes.

## P2 — worth doing

3. **The command palette bypassed the send guard.** `AppShell` ran "Send recap now" and "Send
   test email" unconditionally while `RecapsPage` disabled them — and on mobile the palette
   *is* the primary action surface. **Fixed:** both commands route through a shared guard that
   navigates to Settings with an explanatory toast instead of surfacing a server error.
4. **DESIGN.md described a delete flow the code no longer implements** and PRODUCT.md's
   "reversible beats confirmed" principle read as absolute. **Fixed:** both documents now
   state the hard-delete rationale and the inline-confirm policy.
5. *(nit, not actioned)* Between ~1024 and ~1480px the highlights column left-aligns with a
   ~370px void on the right, because `--gutter` centring only engages past `--measure-view`.
   Centring `.hl-list` independently would break its alignment with the search field and page
   header above it, so it is left as-is deliberately.
