## Design Specificity Verdict

**LLM assessment:** Strongly authored for Relego. The warm paper palette, Playfair display type, ruled reading layout, and three-stage circuit create a documentation surface tied to reading and recollection rather than a generic technical-docs template. Its main weakness is not the visual language: it is the mismatch between the elegant universal story and the actual device and setup paths.

**Deterministic scan:** The CLI detector reported one `broken-image` finding at `src/landing/tests/accessibility.spec.ts:20`. This is a false positive because it detects an HTML string in a test, not rendered documentation. Browser injection succeeded; the overlay reported `overused-font`, `cream-palette`, and `layout-transition`. The first two describe intentional, documented design-system choices. The layout-transition signal is a low-risk implementation observation; the station hover changes color only and does not cause a layout shift.

## Overall Impression

This is a distinctive, calm reading instrument with one strong product-shaped idea: a highlight makes a round trip. The highest-value work is to make that story operationally true for every reader and every starting path.

## What's Working

1. **The Round Trip is memorable.** The vertical spine, numbered stops, and return leg turn a technical setup sequence into a narrative a reader can retain.
2. **The visual system has real restraint.** Warm neutrals, a single terracotta accent, serif display type, and rules rather than cards make long-form technical guidance feel considered without becoming decorative.
3. **The content supports recovery.** Import, delivery, and troubleshooting pages give readers concrete checks rather than generic reassurance.

## Priority Issues

### [P1] The web-first journey stops being web-first

**Why it matters:** Import promises a no-install path, but later guidance to trigger the first recap requires `relego recap trigger`. A first-time reader must silently change tools at the moment they expect a payoff.

**Fix:** Provide equivalent web, Docker, and CLI trigger paths, or state the CLI/Docker requirement before readers commit to the web-upload path. Carry the chosen path through the first recap.

**Suggested command:** `$impeccable onboard`

### [P1] Kobo is not a first-class version of the Round Trip

**Why it matters:** “Back to your reader” sets a device-delivery expectation, while Kobo users ultimately receive mail in an inbox or forward it manually. Discovering that late erodes trust in the overview.

**Fix:** Add a Kobo-specific branch to the Round Trip, Deliver, and Revisit pages. State the distinct final step where it belongs, not as a late exception.

**Suggested command:** `$impeccable clarify`

### [P1] Mobile tables hide critical information without an affordance

**Why it matters:** Import, Revisit, and reference tables preserve content by scrolling, but readers at 390px cannot tell more columns exist. Crucial distinctions can remain unseen.

**Fix:** Prefer labelled stacked records for task tables on small screens. Where a reference table must remain wide, add a visible edge fade and an explicit “Swipe to see more” cue.

**Suggested command:** `$impeccable adapt`

### [P2] SMTP setup asks readers to procure a relay

**Why it matters:** Five comparable relay choices turn a setup step into research and defer the emotional payoff of receiving a first recap.

**Fix:** Recommend one default for this audience with a short rationale. Put remaining services behind an “Other relays” disclosure.

**Suggested command:** `$impeccable onboard`

### [P2] The mobile contents control misstates the reader's location

**Why it matters:** A persistent `Overview` label is ambiguous when the current page is Import, Deliver, Revisit, or a reference page.

**Fix:** Replace the summary label with the current page title, or remove it and keep the `On this page` heading as the sole label.

**Suggested command:** `$impeccable clarify`

## Persona Red Flags

**Jordan, first-time self-hoster:** Chooses the web upload because it says nothing to install, then reaches a CLI command to create a first recap. Jordan's journey has an unexplained tool switch at the highest-motivation moment.

**Priya, Kobo reader:** Understands “back to your reader” as direct device delivery, then discovers a different inbox/manual-forwarding route late in the flow. The overview does not prepare Priya for the actual outcome.

**Alex, privacy-conscious homelabber:** Sees the no-cloud claim before the unauthenticated-server warning. Alex needs the network boundary stated during overview/preflight, before starting Docker.

## Minor Observations

- The small uppercase rail and stage labels are elegant but low-emphasis in dark mode.
- Rename the sidebar's `Introduction` to `Start here` to make its purpose actionable.
- The demo flow is useful, but it risks appearing to be a second setup path instead of a confidence-building shortcut.

## Questions to Consider

- What is the truthful round trip for a Kobo reader?
- Can one chosen setup path reach a first recap without forcing a new tool?
- Why should a reader evaluate SMTP vendors before they can experience the product's payoff?
